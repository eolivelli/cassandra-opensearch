## Summary

This PR adds a new Maven module `hcd-tests` with end-to-end integration tests that prove the full **CQL write → OpenSearch replication** path using the HCD `OpenSearchMutatorInterceptor`, targeting an already-running `docker-compose-full.yaml` stack.

## Key finding: UDT sub-fields and `applyDefaultSchema`

During development we discovered a discrepancy between the documented and actual behaviour of `applyDefaultSchema: true`.

**The README states** that `applyDefaultSchema` maps `text` → `text with a .keyword sub-field`.

**What actually happens** for UDT sub-fields:

The mapping HCD sends at `CREATE CUSTOM INDEX` time includes a `dynamic_template` named `strings_as_text` that maps all dynamically-encountered strings to plain `text` — no `.keyword`. UDT sub-fields (`emails.address`, `phones.number`) are only materialised at first document insertion, at which point they hit this template. Top-level columns (`full_name`) are correctly emitted as static properties with `.keyword` at index creation time.

**Consequence:** `term` queries on `emails.address.keyword` silently return 0 hits — no error, just an empty result set. `match_phrase` is the correct workaround.

**Actual mapping sent by HCD (before any document insertion):**
```json
{
  "dynamic_templates": [
    { "strings_as_text": { "match_mapping_type": "string", "mapping": { "type": "text" } } }
  ],
  "properties": {
    "full_name": { "type": "text", "fields": { "keyword": { "type": "keyword", "ignore_above": 256 } } },
    "emails":    { "type": "object", "dynamic": "true" }
  }
}
```

This is worth addressing in two ways:
1. **Documentation:** Update the `applyDefaultSchema` description to clarify that the `.keyword` guarantee applies to top-level columns only, not UDT sub-fields.
2. **Behavioural improvement (optional):** When `applyDefaultSchema: true`, the UDT schema is fully known at `CREATE INDEX` time — HCD could walk it recursively and emit static `properties` for UDT sub-fields, giving them `.keyword` sub-fields the same way top-level columns receive them today.
